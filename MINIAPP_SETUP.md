# Запуск мини-приложения TimeBalance

Для локальной демонстрации после заполнения `.env` запустите
`docker compose up --build`: поднимутся PostgreSQL, API и бот. Затем откройте
`http://127.0.0.1:8000/miniapp/`.

Для запуска из MAX публичный HTTPS-адрес должен вести на тот же API-контейнер,
а URL `/miniapp/` должен быть заранее указан в настройках бота MAX. После этого
проверяющий открывает чат с ботом, пишет `/start` и нажимает кнопку
«Открыть мини-приложение». Динамический туннель с новым URL потребует
повторной привязки в MAX; для показа используйте постоянный адрес.

Фронтенд и API теперь работают на одном FastAPI-сервере. Запустите `python code.py` из корня репозитория и откройте `http://127.0.0.1:8000/miniapp/`. В обычном браузере доступен локальный демо-режим.

Для работы внутри MAX:

1. Установите зависимости из `requirements.txt` и укажите `MAX_BOT_TOKEN` в локальном `.env` (см. `.env.example`).
2. Разместите весь сервер на постоянном HTTPS-адресе и задайте `DATABASE_URL` для PostgreSQL. GitHub Pages для этой версии недостаточно: оно отдаёт статические файлы, но не запускает API.
3. В настройках бота MAX укажите адрес `https://ваш-домен/miniapp/`. В `.env` установите `MINI_APP_URL` в тот же адрес.
4. Откройте мини-приложение через MAX. Клиент передаст подписанный `window.WebApp.initData` на `/api/v1/auth/max`, после чего дела и настройки будут храниться на сервере.

Проверка API: `/health` и `/docs`. Секреты не размещайте во фронтенде или Git.
