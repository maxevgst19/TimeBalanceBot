# TimeBalance

TimeBalance — планировщик учебного дня в мини-приложении MAX. Он собирает занятия, дорогу, домашние задания и отдых на одной шкале, показывает свободные окна и заранее предупреждает, если дел больше, чем времени. Для перегруженного дня предлагает несколько вариантов «Плана Б» с видимыми последствиями каждого варианта.

Проект рассчитан на школьников и студентов с плотным расписанием. Для проверки без аккаунта MAX есть браузерный демо-режим.

## Возможности

- **Сегодня:** шкала дня, ближайшее действие, свободное время и причины перегрузки.
- **Неделя:** обзор занятости и проверка, поместится ли новое дело в расписание.
- **Дела и задания:** создание, редактирование, удаление, повторение по дням недели, шаблоны и учёт фактически потраченного времени.
- **Заметки:** запись на выбранный день или к конкретному занятию. Бот напоминает о заметке на день после 09:00, о заметке к занятию — за 15 минут до начала.
- **Афиша:** мероприятия выбранного города из СПОНТАННО и напоминания о сохранённых событиях.
- **План Б:** варианты переноса или разделения задач, когда расписание перегружено.

Интерфейс выполнен как пинборд с заметками и карточками. Доступны светлая и тёмная темы. В MAX данные хранятся в PostgreSQL; в обычном браузере демо-данные хранятся локально на устройстве.

## Быстрый запуск для ревьюэра

Нужны Docker и Docker Compose. Из корня репозитория выполните:

```bash
docker compose up --build -d
```

Затем откройте [мини-приложение](http://127.0.0.1:8000/miniapp/). Без токена MAX оно работает в браузерном демо-режиме: можно добавлять дела, проверять план и пользоваться интерфейсом. API доступен на `http://127.0.0.1:8000/docs`, проверка сервера — на `http://127.0.0.1:8000/health`.

Команда поднимает приложение и PostgreSQL. База сохраняется в Docker volume между перезапусками. Остановить проект можно командой `docker compose down`.

## Запуск через MAX

Для работы бота нужен токен своего бота MAX. Создайте `.env` по образцу `.env.example`, укажите `MAX_BOT_TOKEN` и снова выполните `docker compose up --build -d`. После запуска отправьте боту `/start`.

Для открытия мини-приложения **внутри MAX** в настройках бота должен быть указан публичный HTTPS-адрес этого же приложения с путём `/miniapp/`. Локальный адрес `127.0.0.1` доступен только на компьютере, где запущен Docker; для телефона понадобится развёртывание на сервере или HTTPS-туннель. Кнопка «Открыть мини-приложение» в ответе на `/start` использует адрес, привязанный к боту в MAX.

Уведомления, включая заметки и мероприятия, приходят только пользователю, который вошёл в мини-приложение через MAX и включил уведомления в профиле. Браузерный демо-режим не отправляет сообщения в чат.

## Локальный запуск без Docker для приложения

Нужны Python 3.12+ и PostgreSQL. Можно запустить только базу через `docker compose up -d postgres`, установить зависимости и выполнить:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python server.py
```

В `.env.example` уже указан адрес PostgreSQL из `compose.yaml` для запуска приложения на хосте. На Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate` и скопируйте `.env.example` в `.env` любым доступным способом.

## Проверка

После запуска PostgreSQL тесты можно выполнить так:

```bash
TEST_DATABASE_URL=postgresql://timebalance:timebalance_dev@127.0.0.1:5433/timebalance python -m pytest -q
```

Каждый API-тест создаёт отдельную временную схему и удаляет её после проверки. Тесты покрывают авторизацию MAX, API, расчёт плана и время отправки заметок. Собранные файлы мини-приложения лежат в `miniapp/`; после изменения исходников в `miniapp/src/` обновите их командой `python tools/build_miniapp.py`.

## Устройство проекта

| Путь | Назначение |
|---|---|
| `app/` | FastAPI, расчёт расписания, работа с PostgreSQL, бот и уведомления |
| `miniapp/src/` | Исходники интерфейса |
| `miniapp/index.html`, `miniapp/app.min.js` | Готовая миниапка, которую раздаёт сервер |
| `tests/` | Проверки API и логики планирования |
| `compose.yaml`, `Dockerfile`, `server.py` | Запуск проекта |

Сервер сам создаёт таблицы при первом старте. Токен и другие локальные настройки хранятся в `.env`, который исключён из Git.
