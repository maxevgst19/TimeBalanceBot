# TimeBalance

**TimeBalance** — мини-приложение в MAX, которое показывает школьнику его реальный день:
занятия, дорогу, задания, свободные окна и отдых. Когда дела не помещаются, оно
показывает дефицит времени на наглядной шкале и предлагает несколько вариантов
«Плана Б».

Репозиторий содержит и **бэкенд** (REST API и чат-бот MAX), и **готовое
мини-приложение** на чистом HTML/CSS/JS, которое работает без сборщика.

- Концепция продукта — [`PROJECT_CONCEPT.md`](PROJECT_CONCEPT.md)
- Контракт API — [`openapi.yaml`](openapi.yaml)
- Стандарт интерфейса — [`DESIGN_STANDARD.md`](DESIGN_STANDARD.md)

## Что делает мини-приложение

| Экран | Что видит пользователь |
|---|---|
| **Сегодня** | Карточка «Сейчас» с одним выполнимым шагом, вертикальная шкала дня, свободные окна и итог: сколько свободно и сколько запланировано. Если дел не хватает — карточка «Не хватает N минут» с причиной и кнопкой «Собрать План Б». |
| **Неделя** | Семь дней с суммарной занятостью, свободными минутами и отметками конфликтов. |
| **План Б** | 2–3 варианта перестройки дня. Каждый показывает, что переместится или разделится, и **оставшийся дефицит до нажатия «Применить»**. После применения план пересчитывается. |
| **Добавить** | Короткая форма: для занятия — название, начало, конец; для задания — название, срок, длительность. Дополнительно — повторение, дорога, переносимость, делимость. |
| **Профиль** | Личные границы: время окончания учебных дел, перерыв после школы, уведомления, «Сбросить данные». |

Главное обещание продукта — показать, что дела **не помещаются**, до того как вечер
уже сорван, и предложить выбор, а не «постараться сильнее».

Приложение стартует пустым: демо-дел нет, пользователь добавляет свои. Кнопка
«Сбросить данные» очищает дела и занятия и возвращает настройки по умолчанию.

## Как считается план

Алгоритм — работа интервалами без ИИ (`app/planning/engine.py`, раздел 9
`PROJECT_CONCEPT.md`):

1. строятся занятые интервалы: события, дорога до/после, перерыв после школы;
2. внутри `[начало учебного дня, окончание учебных дел]` ищутся свободные окна;
3. задачи раскладываются по окнам по срочности: делимые — кусками, неделимые —
   только в окно нужной длины;
4. неразмещённые минуты превращаются в конфликт с точным числом и причиной:
   `time_shortage` (общий дефицит), `deadline` (задача не влезает в окно),
   `overlap` (пересечение занятий или дороги);
5. из конфликта собираются варианты «Плана Б» — каждый сначала применяется к копии
   данных, план пересчитывается, и пользователю показывается остаточный дефицит
   (`app/planning/alternatives.py`).

Отдых защищён: задачи никогда не ставятся после `day_end`, а обязательный перерыв
после школы — такой же занятый блок, как урок.

## Стек

| Часть | Выбор |
|---|---|
| API | FastAPI + Pydantic (схемы повторяют `openapi.yaml`) |
| Бот | [`pymaxbot`](https://github.com/svkurick/max_bot) — Python SDK MAX |
| База | SQLite через `aiosqlite` |
| Время | `zoneinfo`, часовой пояс из профиля пользователя |
| Мини-приложение | HTML + CSS + vanilla JS, данные в `localStorage` |

## Запуск

```bash
pip install -r requirements.txt

# Linux / macOS
cp .env.example .env
# Windows PowerShell
Copy-Item .env.example .env

# вписать в .env MAX_BOT_TOKEN и (при необходимости) MINI_APP_URL
python code.py            # http://127.0.0.1:8000
```

`code.py` запускает REST API и чат-бот MAX в одном процессе. Если зависимости
бэкенда не установлены, он запускает облегчённого бота из `bot/max_bot.py` —
без API, но с рабочей кнопкой входа в мини-приложение.

Файл `.env` в корне проекта загружается автоматически при старте
(`Settings.from_env()` → `python-dotenv`), отдельных переменных окружения
задавать не нужно. При этом **реальные переменные окружения имеют приоритет**:
если `MAX_BOT_TOKEN` уже задан в системе, значение из `.env` его не перезапишет.

Swagger UI — `http://127.0.0.1:8000/docs`, спецификация — `/openapi.json`
(пути относительны к `/api/v1`, как в `openapi.yaml`).

### Демо-хостинг мини-приложения

Если `MINIAPP_MODE=link` и адрес не задан, `code.py` сам поднимает локальный
сервер с `miniapp/` и HTTPS-туннель через [localhost.run](https://localhost.run)
(обычный `ssh`, без регистрации). В консоли появится адрес вида
`https://xxxx.lhr.life` — на него ведёт кнопка в боте. Адрес живёт, пока запущен
`code.py`; при перезапуске он меняется.

### Сертификаты Минцифры

MAX API работает с сертификатами Минцифры. Они уже лежат в `certs/`
(`russian_trusted_root_ca.pem`, `russian_trusted_sub_ca.pem`), облегчённый бот
подключает их автоматически вместе с системными. Без них будет ошибка
`CERTIFICATE_VERIFY_FAILED`.

### Переменные окружения

См. [`.env.example`](.env.example). Основные:

- `MAX_BOT_TOKEN` — токен бота; без него работает только API, бот и уведомления отключаются;
- `MINI_APP_URL` — ссылка, которую бот отдаёт по кнопке (бэкенд);
- `MINIAPP_URL` — та же ссылка для облегчённого бота; `code.py` синхронизирует обе;
- `DAY_START` / `профиль пользователя.day_end` — границы учебного дня;
- `TIMEBALANCE_DB` — файл базы SQLite.

Всё это можно задать либо в `.env`, либо настоящими переменными окружения —
работает и то, и другое.

**Токен и другие секреты в репозиторий не попадают:** `.env` в `.gitignore`,
`.env.example` содержит только плейсхолдеры.

## Подключение мини-приложения внутри MAX

Режим кнопки облегчённого бота задаётся переменной `MINIAPP_MODE`:

| Режим | Что делает кнопка |
|---|---|
| `mini_app` (по умолчанию) | `open_app` — открывает мини-приложение **внутри MAX** |
| `link` | обычная ссылка, открывается в браузере (для быстрого теста; `code.py` сам поднимает туннель) |

Как сделать настоящее мини-приложение внутри MAX:

1. Выложи папку `miniapp/` на **HTTPS**-хостинг (GitHub Pages, VK Cloud, Yandex Cloud). URL должен быть постоянным.
2. Открой [business.max.ru](https://business.max.ru/self) → **Чат-боты** → нужный бот → **⋮ → Настройки**.
3. Вставь URL мини-приложения в поле для ссылки, выбери кнопку **«Открыть»** и сохрани.
4. Впиши этот же адрес в `.env` как `MINIAPP_URL=https://...` и `MINI_APP_URL=https://...`.

> Важно: `open_app` не содержит URL. Адрес мини-приложения хранится только в
> настройках бота на стороне MAX, поэтому привязать его из кода нельзя.

## Мини-приложение

Интерфейс сделан по `DESIGN_STANDARD.md`: светлая «тетрадь», токены цветов,
крупная шкала дня и спокойные формулировки.

- **Сегодня** — карточка «Сейчас», конфликт с точным дефицитом минут, шкала дня
  (занятия, дорога, отдых, задания, свободные окна), итог дня.
- **Неделя** — семь строк с нагрузкой и пометкой конфликта.
- **План Б** — варианты перестройки, изменения и остаточный риск до применения.
- **Профиль** — граница учебного дня, перерыв после школы, уведомления, сброс данных.
- **Добавить** — нижний лист: «Задание» или «Занятие», быстрая проверка полей.

Исходники лежат в `miniapp/src/`, а `miniapp/index.html` и `miniapp/app.min.js`
собираются из них. Правь `src/`, затем запускай:

```powershell
.venv\Scripts\python tools\build_miniapp.py
```

Сборка нужна из-за бесплатного туннеля: он обрывает большие ответы. CSS
встраивается в страницу, поэтому получается два запроса вместо трёх, а после
gzip каждый ответ меньше 10 КБ. Если JS не загрузился с первого раза, страница
сама пробует ещё дважды и показывает кнопку «Повторить» — стили при этом видны
сразу, потому что они внутри HTML.

Данные хранятся в `localStorage`; расчёт плана пока выполняется на клиенте по
правилам из `PROJECT_CONCEPT.md`. Когда фронтенд переключат на API, места расчёта
заменяются вызовами из `openapi.yaml` (`/plan`, `/plan/next-action`,
`/plan/alternatives`).

Локальный предпросмотр (показывает уже собранную версию):

```powershell
cd miniapp
python -m http.server 8080
```

## Чат-бот — проводник

Бот не планирует: его роль ограничена (раздел 8 концепции).

- `/start` — короткое описание продукта и кнопка **«Открыть мини-приложение»**;
- `/help` — список команд;
- уведомления от сервера — редкие и полезные: «Среда перегружена: не хватает
  45 минут. Открой План Б» и напоминание за 15 минут до события. Одна причина —
  одно сообщение в сутки (дедупликация в `notifications_sent`).

Один школьник в боте и в мини-приложении — одна запись: бот заводит профиль по
`user_id` из MAX, а мини-приложение связывается с ним при первом входе по
подписанному `initData`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/max` | Обмен проверенного `initData` на сессию |
| GET/PATCH | `/me` | Профиль и личные границы |
| DELETE | `/me/data` | Полное удаление данных пользователя |
| GET/POST | `/events` | Уроки, кружки и другие занятия (с повторениями) |
| PATCH/DELETE | `/events/{eventId}` | Изменить или удалить событие |
| GET/POST | `/tasks` | Задания со сроком и длительностью |
| PATCH/DELETE | `/tasks/{taskId}` | Изменить, закрыть или удалить задание |
| GET | `/plan` | План: блоки, конфликты, свободное и запланированное |
| GET | `/plan/next-action` | «Что делать сейчас» |
| POST | `/plan/alternatives` | Варианты «Плана Б» с последствиями |
| POST | `/plan/alternatives/{id}/apply` | Применить вариант и пересчитать план |

Все даты — ISO 8601 с часовым поясом, длительности — в минутах, диапазон плана —
не больше 31 дня. Ошибки всегда в формате `{"code", "message", "details"}`.

Тесты покрывают подпись `initData` (подделка, дубликаты параметров, срок),

применение варианта «Плана Б».

## Ограничения MAX

- Подключение к платформе доступно юрлицам, ИП и самозанятым — резидентам РФ, бот проходит модерацию.
- Long polling подходит для разработки и демо; для production нужен Webhook (`POST /subscriptions`).
- Запросы идут на `https://platform-api2.max.ru`; при проблемах с TLS добавь сертификат Минцифры в доверенные.
